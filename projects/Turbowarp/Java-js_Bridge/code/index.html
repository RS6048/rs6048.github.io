Source Code: Java-js Bridge

Source Updated: 2026-11-15

The complete source of the desktop host described in the paper: the Swing/JCEF host, the message-router handler that implements the bridge protocol, the favicon pre-reader, the unsandboxed TurboWarp extension, and the two Gradle build scripts. These files are the state that produced the measurements in Section 4.5 and Section 4.6 of the paper — the window layer, including the fixed-size policy.

Building

The project is built with Gradle and the Shadow plugin, producing a single runnable fat jar with the native jcefmaven libraries merged in. No runtime download is needed afterwards, but the resulting jar is large (about 171 MB) because it carries the whole Chromium build.

# JDK 21 is required (the classes are compiled for class file version 65)
gradle shadowJar

# output
build/libs/WebGUI-1.0-SNAPSHOT-all.jar

Dependencies are taken from an Aliyun / Tencent Cloud mirror first and Maven Central second (see the repositories block), which is what makes the jcefmaven natives available behind a slow direct connection to Maven Central.

Running

The same JVM flags as in Section 5.1 are mandatory, because JOGL reaches into JDK-internal AWT packages. Adjust the window with the named flags of Table 3 — any order, -flag value or -flag=value:

java \
  --add-exports java.base/java.lang=ALL-UNNAMED \
  --add-exports java.desktop/sun.awt=ALL-UNNAMED \
  --add-exports java.desktop/sun.java2d=ALL-UNNAMED \
  --add-opens java.desktop/sun.awt=ALL-UNNAMED \
  -jar WebGUI-1.0-SNAPSHOT-all.jar -html Project.html -y 700 -x 1000

The working directory matters: jcef-bundle, the HTML file and the paths the project passes to the blocks are all resolved relative to it.

Notes on these copies

  • Main.java is kept with CRLF in the local working tree and stored here with LF; apart from the line terminators the text is byte-identical. Every other file is byte-identical, including extension.js and the Gradle scripts.
  • Nothing here is minified or rewritten for the web. The files are the ones that were compiled and measured, comments included — that is why the [GEOM] and [FORCERESIZE] diagnostics described in Section 4.6 are present in Main.java.
  • All files are UTF-8 without a byte-order mark. The .java files are served as text/x-java-source without a charset, so a browser that guesses the encoding may show the Chinese comments as mojibake; use the view link for a correctly decoded copy.
  • The binary assets on the release page were built separately; if you enable or change the window layer yourself, rebuild rather than mix these sources with an older jar.

These files are published for reading. The bridge runs unsandboxed with the permissions of the current user — review Section 6 of the paper before pointing it at anything you care about.
