Java-js Bridge: Local File Access for TurboWarp Projects via JCEF

Ongoing Updated: 2026-10-01

Abstract

TurboWarp compiles Scratch projects into JavaScript and runs them inside a browser sandbox, which blocks direct access to the host filesystem. This paper describes Java-js Bridge, a desktop host built on the Java Chromium Embedded Framework (JCEF). It registers a message router that injects a JS↔Java bridge (window.cefQuery) into the embedded page, and exposes eight file-operation blocks to TurboWarp projects through an unsandboxed custom extension. The design, protocol, implementation and usage of the system are presented.

1. Introduction

TurboWarp is an accelerated compiler for Scratch projects [4]. A compiled project behaves like a web page: it runs inside a sandbox, and web security rules deliberately prevent a page from silently reading arbitrary files on the host machine. Two ordinary approaches are unusable here:

  • fetch("file://...") is blocked by browsers.
  • The File System Access API requires a user gesture and a file-picker dialog for every single file, which is impractical for projects that need to auto-load whole folders of textures, sound banks or save data.

Consequently, a locally packaged TurboWarp project has no reliable way to touch the files next to it. The goal of this work is to restore that capability in a controlled manner.

2. Architecture

The system replaces the browser itself. JCEF is the Java port of the Chromium Embedded Framework [3], embedding a full Chromium browser inside a Swing application. The host registers a message router (CefMessageRouter) that injects the JS↔Java bridge window.cefQuery into every page of the embedded browser [1]. A custom, unsandboxed TurboWarp extension exposes this bridge to Scratch in the form of blocks.

The bridge chain is: Scratch block → extension.js → window.cefQuery → CefMessageRouter → FileMessageRouterHandler (Java) → local file. The overall architecture is shown in Figure 1.

3. Bridge Protocol

All communication between the page and the Java host is JSON transported over window.cefQuery. A request carries an action, a path and optional data; the host answers with a status flag and either the result or an error message, as shown below.

// Request (from the page to Java)
{ "action": "readFile", "path": "data.txt", "data": "hello" }

// Response (from Java back to the page)
{ "ok": true,  "data": "file content..." }   // success
{ "ok": false, "error": "message" }          // failure

Eight actions are supported (Table 1).

4. Implementation

The system consists of four components, described below.

4.1 Host Application (Main.java)

  • Initializes CefApp via jcefmaven's CefAppBuilder with install directory jcef-bundle; native libraries ship as Gradle dependencies, so no runtime download is required.
  • Keeps the GPU enabled — --disable-gpu must stay commented out because TurboWarp projects rely on WebGL hardware acceleration.
  • Enables off-screen rendering (windowless_rendering_enabled = true) so the browser embeds cleanly into a Swing window.
  • Attaches the CefMessageRouter with the file handler to the client, loads Project.html (the TurboWarp packager output) from file:///, and mirrors the page title into the window via CefDisplayHandlerAdapter.onTitleChange.
  • Loads the project's favicon on a background thread and sets it as the frame icon; on window close, browser.close(true) and cefApp.dispose() release all native resources.

4.2 Message Router Handler (FileMessageRouterHandler.java)

  • Extends CefMessageRouterHandlerAdapter; onQuery parses the JSON request and dispatches by action.
  • All operations use java.nio.file (Files.readAllBytes, Files.write, Files.createDirectories, Files.list, Files.deleteIfExists, Files.size).
  • Requests are executed on a 4-thread executor so the CEF UI thread is never blocked; CefQueryCallback.success is thread-safe.
  • Errors are caught and returned as {"ok":false,"error":...} instead of crashing the page.

4.3 TurboWarp Extension (extension.js)

  • Requires the extension sandbox to be disabled: it throws "Run it unsandbox!!!" otherwise, because only unsandboxed extensions may touch window.cefQuery.
  • callJava(payload) wraps window.cefQuery into a Promise; exec(action, path, data) builds the payload, checks ok and returns data.
  • Exposes the green Local File category with eight blocks, detailed in Section 5.2.

4.4 Favicon Loading (FaviconLoader.java)

  • Scans the HTML for <link rel="..."> icons with priority apple-touch-icon > shortcut icon > icon.
  • Handles relative/absolute file paths, http(s) URLs and data: URIs; decodes PNG/JPEG/GIF/BMP and ICO files with embedded PNGs (SVG is skipped).
  • Enforces a 2 MB limit; any failure silently returns null.

5. Usage

5.1 Setup

  1. Place Project.html (the TurboWarp packager output) next to the application and start it. A Swing window opens with the project inside an embedded Chromium.
  2. In the project, load the Local File extension in unsandboxed mode — it refuses to start otherwise.
  3. Build blocks from the Local File palette.

Figure 2 shows the extension being loaded in the editor, and Figure 3 shows the running application window.

5.2 Block Reference

Each block is presented in its own subsection, with a demonstration shown as a short animation.

5.2.1 read [PATH] Reporter

Reads a file and returns its content as a UTF-8 string. Suitable for loading text assets, configuration files or save data.

5.2.2 write [DATA] into [PATH] Command

Overwrites a file with the given data, creating parent directories as needed.

5.2.3 append [DATA] to [PATH] Command

Appends text to a file, creating it if it does not exist.

5.2.4 list directory [PATH] Reporter

Lists the entries of a directory as a JSON array string, each item carrying name, isDir and size.

5.2.5 exists [PATH] Boolean

Reports whether the given path exists.

5.2.6 delete [PATH] Command

Deletes a file or an empty directory.

5.2.7 make directory [PATH] Command

Recursively creates directories.

5.2.8 file size of [PATH] Reporter

Returns the file size in bytes, or 0 on failure.

5.3 Example

A minimal auto-save routine combining the blocks above:

when green flag clicked
if <exists [save.txt]> then
    set [content v] to (read [save.txt])     // reporter -> file text
    say (content)
else
    write [hello] into [save.txt]            // command, awaits completion
end

Reporter and boolean blocks return their value directly to Scratch; command blocks finish asynchronously and the next block runs after the operation completes. This is sufficient to build auto-save, level editors, asset loaders or text-based games that read and write real files on disk.

6. Security Considerations

  • The unsandboxed extension runs with the same permissions as the current user. A historical TurboWarp Desktop bug (CVE-2023-40168 [6]) allowed a malicious project to exfiltrate arbitrary files, so this bridge should only be enabled for trusted projects.
  • For untrusted projects, set ROOT_LIMIT in FileMessageRouterHandler to an allow-listed directory; paths are normalized and prefix-checked, blocking ../ traversal.
  • Never load unknown projects or unknown extensions into this application.
